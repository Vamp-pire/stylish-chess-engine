이 문서는 로컬 세션에서 하던 작업을 클라우드 세션이 이어받기 위한 요약이다.
작업 중인 코드는 브랜치 `wip/speed-ux-retention`에 있다 (main에 아직 안 합침 = 배포 안 됨).

## 사용자·프로젝트 규칙 (꼭 지킬 것)
- 사용자와 대화는 **한국어**. 화면 문구는 `tr('한국어', 'English')`로 두 언어 모두.
- 큰 기능은 **계획을 먼저 말하고 승인**받은 뒤 만든다. 사용자가 이미 지시한 범위는 바로 진행.
- 배포 = main에 커밋 후 push (Cloudflare Pages 자동 배포, https://stylish-chess-engine.pages.dev). 이 프로젝트에선 승인된 방식.
- 커밋 메시지 끝: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
- 서버 쪽 분석·유료 홍보 제안 금지. 엔진 해시 리셋(ucinewgame) 넣지 말 것. 멀티스레드 Stockfish는 테스트 결과 2~5배 느려 제외 (재제안 금지).
- 디시·디스코드 피드백은 그대로 믿지 말고 코드·데이터로 검증 후 반영.

## 브랜치 `wip/speed-ux-retention`에 있는 미완성 작업
모두 `npx tsc --noEmit` 통과. **브라우저 확인·전체 테스트는 아직 안 함.**

### 속도
| 항목 | 파일 | 상태 |
|---|---|---|
| 종합 분석 깊이 10 고정(선택지 제거), 2판 동시 분석, 남은 시간 표시, 새로고침 후 이어서 분석 배너 | src/main.ts (`BATCH_DEPTH`, `BATCH_CONCURRENCY`, `runBatch`, `batchEta`, `PENDING_KEY`) | 구현됨, 브라우저 확인 필요 |
| 국면 캐시 (IndexedDB, 4만 개 상한) | src/engine/positionCache.ts, src/ui/runner.ts | 구현됨, 확인 필요 |
| 엔진 개수 최대 6 (8코어 측정: 4개 5.4~7.0초 → 6개 4.4초) | src/engine/browser.ts | 구현됨 |
| scout(얕게 먼저 → 기운 국면·이론 국면은 얕은 결과), reusePlayed(둔 수 추가 분석 생략) | src/core/analyzer.ts (`AnalyzeOptions.scout/reusePlayed`) | **옵션만 추가, 기본 꺼짐.** A/B 측정 필요 |
| Maia WebGPU | src/human/maia3.ts (`createMaia3(ort, model, options, batchSize)`), 테스트 src/_tmp-maia-gpu.ts | **측정 결과: CPU 80국면 20.7초 → WebGPU 7.6초 (2.7배), 상위 수 같음, 확률 차 0.001.** 아직 maia.worker.ts에 적용 안 함 |

**중요 발견:** 분석 병목은 Stockfish(깊이 10)보다 **Maia3**다. 16국면 예측 5.7초 → 한 판(80국면) 약 28초 (CPU, 다른 작업과 경합 중 측정).

남은 속도 작업:
1. Maia WebGPU 적용: `src/human/maia.worker.ts`에서 `navigator.gpu`가 있으면 `onnxruntime-web/webgpu` + `{ executionProviders: ['webgpu'] }`, 실패하면 지금처럼 wasm. 배치 크기 32/80도 비교 (`_tmp-maia-gpu.ts`에 측정 코드 있음, 브라우저에서 `await (await import('/src/_tmp-maia-gpu.ts')).run()`).
2. Maia 질의 줄이기: 오프닝 이론 국면은 Maia를 생략 (보정 지표 rare에 영향 없는지 확인 — rare는 이론 수를 빼고 센다).
3. scout·reusePlayed A/B: `npx tsx scripts/_tmp-speedab.mts <결과파일> 14` (깊이 10, 기본/scout/reuse/둘다 시간·품질 일치·유형 지표 차이). 로컬에서 한 판 ~8분이라 3판까지만 돌았음. 유형 지표 차이가 보정 표준편차 0.1 미만이고 품질 일치 95% 이상이면 기본값으로 켜고, 켜면 **보정 데이터도 같은 옵션으로 다시 만들어야** 한다(.github/workflows/calibrate.yml).
4. 페이지 로딩 성능 (Lighthouse: SEO 100, 성능 30~48): 첫 화면 유형 PNG 3.7MB → WebP·작은 크기·lazy (sharp가 devDependency로 설치됨, 아직 이미지 생성 코드 없음), Pretendard 글꼴·AdSense·Clarity 렌더링 차단 완화, /app CLS 0.327 원인 찾기. 사용자가 "알아만 두고 나중에" 하라고 함.

## 사용자 결정 대기 중
1. **유형 축 재구성** (데이터 근거 있음, 승인 대기). 3,604명 반분 신뢰도(5판 vs 5판):
   - A/P 0.15 → 0.31: P쪽을 포지셔널·예방 대신 공간·긴장 + "비슷한 대안 중 선택(choiceDelta)" 추가
   - W/S 0.32 → 0.40: 위험수 비율 빼고 복잡화·안정·단순화의 선택 성향 추가
   - I/R 0.20 → 0.25: 활동성·선택 성향 추가 / O/E 0.56 그대로
   - 측정 스크립트: scripts/calib/axis-candidates.mjs, reliability.mjs, stability.mjs. 데이터: Actions run 38380468117 아티팩트 `type-calib`의 all.jsonl.gz (보존 30일).
   - 현재 축으로는 5판 재현율 네 글자 모두 13% (우연 6%), 10판 축별 ~60%. 기본 분석 판 수 늘리기(20~30판)와 함께 해야 의미 있음.
2. 매주 자동 콘텐츠 승인 여부.

## Search Console 사이트맵 "가져올 수 없음"
사이트맵 자체는 정상 확인함: 200, application/xml, Googlebot 접근 가능, 43개 주소 모두 200·리다이렉트 없음.
사용자에게 안내할 것: 속성이 `https://stylish-chess-engine.pages.dev/`(URL 접두어)인지 확인 → 기존 사이트맵 삭제 후 `sitemap.xml` 다시 제출 → URL 검사에서 사이트맵 주소 "실시간 테스트". 처음 제출 실패 상태가 며칠 남는 경우가 흔함.
