# 재방문 기능 + 가벼운 서버 계획 (2026-10-14 사용자 승인)

## 정한 것
| 항목 | 결정 |
|---|---|
| 서버 역할 분담 | Cloudflare = 링크 미리보기·짧은 주소·악용 방지 / Supabase = 모든 데이터·자동 정리·관리 화면 / GitHub Actions = 오늘의 문제 생성 |
| 동기화 코드 보관 | **마지막 사용 후 30일** 지나면 자동 삭제 |
| 그룹 지도 이름 | **기본은 체스 아이디**, 원하면 닉네임으로 바꿀 수 있음 |
| 오늘의 문제 교체 | **한국 시간 자정** (전 세계 같은 문제) |
| 작업 장소 | 이 로컬 세션. 클라우드 세션 배포가 끝난 뒤 시작 (같은 파일 동시 수정 방지) |
| 서버에서 분석 | 사용자별 엔진 분석은 서버에서 하지 않음 (Supabase Edge Functions 요청당 CPU 약 2초, Cloudflare Workers 무료 10ms라 불가). 미리 할 수 있는 계산은 GitHub Actions에서 하고 결과만 Supabase에 저장. 국면 공유 캐시는 오염 방지 장치가 필요해 사용자가 늘면 재검토 |

## 역할 분담 (각자의 장점)
- **Cloudflare (사이트가 있는 곳)**
  - 링크 미리보기: 카톡·디스코드는 링크를 붙이면 우리 주소의 HTML을 직접 읽으므로, Pages Functions가 링크별 제목·이미지를 끼워 넣는다 (기존 유형 이미지 16장 사용, 그림 생성 없음).
  - 짧은 주소: `/u/lichess/아이디`, `/u/chesscom/아이디`, `/g/그룹코드`
  - 악용 방지: Turnstile(사람 확인)·요청 횟수 제한
- **Supabase (데이터베이스)**
  - 테이블: 오늘의 문제, 정답 기록(통계), 그룹, 그룹 멤버, 동기화
  - 접근 규칙(RLS)으로 남의 데이터 수정 금지, 익명 로그인으로 브라우저마다 식별
  - pg_cron으로 30일 지난 동기화 코드 자동 삭제
  - 대시보드에서 그룹 닉네임 확인·삭제(관리)
- **GitHub Actions (무료 계산)**
  - 매일 한국 시간 자정 전에 다음 날 문제를 골라 Supabase에 저장 (이게 무료 프로젝트 7일 비활동 정지도 막아 줌)
  - 유형 궁합·유형별 오프닝 데이터 생성 (정적 페이지용)

## 단계

### 1단계 — 서버 없이 (계획 그대로 보관)
1. **아이디 고정 주소**: `/u/lichess/아이디`를 열면 지난번 이후 새 게임만 바로 분석. 결과 화면에 "이 주소를 즐겨찾기 하세요". PC용 북마클릿(즐겨찾기 줄로 끌어다 놓는 버튼: Lichess·Chess.com 게임 화면에서 누르면 그 게임을 Stylish로 보냄)도 덤으로.
2. **월간 결산 카드**: 이번 달 유형·가장 대담했던 수·정확도 변화를 결과 이미지 형식으로 공유. 매월 초 "지난달 결산" 배너.
3. **유형 궁합 페이지(136쌍) + 유형별 어울리는 오프닝**: 정적 페이지, 검색 유입용. 오프닝은 클라우드 세션이 만든 오프닝 스타일 데이터(3,332개) 사용.

### 2단계 — Supabase 준비 (사용자 할 일은 아래 별도 정리)
- 익명 로그인(브라우저마다 고유 ID) + RLS
- 테이블 SQL은 내가 작성하고, 실행은 사용자가 함
- 개인정보처리방침에 추가: 익명 ID, 오늘의 문제 정답 기록, 그룹 이름(체스 아이디 또는 닉네임)·유형, 동기화 데이터(30일 후 삭제)

### 3단계 — 오늘의 유형 맞히기 + 전체 통계
- **문제**: GitHub Actions가 보정 데이터(익명화된 Lichess 플레이어, CC0)에서 **네 축 모두 가운데에서 멀리 떨어진** 플레이어를 골라 특징적인 수 3~4개를 보여준다 (유형이 흔들리는 문제 때문에 뚜렷한 사람만).
- **진행**: 4글자 맞히기, 기회 4번, 글자마다 🟩(맞음)/⬜(틀림)
- **공유**: `Stylish #12 🟩⬜🟩🟩 / 🟩🟩🟩🟩 2/4 stylish-chess-engine.pages.dev` 이모지 결과 복사 (답은 안 보임)
- **연속 기록**: 브라우저 저장 (동기화 코드로 기기 간 이어짐)
- **전체 통계**: 오늘 정답률, 몇 번 만에 맞혔는지 분포, "상위 N%". 같은 익명 ID는 하루 한 번만 기록

### 4단계 — 링크 미리보기
- 비교 링크(`/app?vs=…`), 아이디 고정 주소, 그룹 링크, 오늘의 문제 결과를 공유하면 유형 카드가 미리보기로 뜬다.
- Cloudflare Pages Functions가 HTML의 og:title·og:description·og:image만 바꿔 끼움 (기존 유형 이미지 사용).

### 5단계 — 그룹 유형 지도
- 그룹을 만들면 코드가 생기고, **자기가 속한 그룹을 코드(링크 `/g/코드`)로 공유**한다.
- 그룹 화면: **16칸 지도 + 인원 분포**
- **유형은 자동으로 들어가고 업데이트**: 그룹에 들어간 브라우저에서 종합 분석이 끝날 때마다 그 사람의 최신 유형으로 자동 갱신 (판이 적어 '애매'한 유형은 표시 구분)
- 이름: 기본은 체스 아이디, 원하면 닉네임으로 변경
- 악용 방지: **닉네임 길이 제한, 금칙어, 같은 브라우저(익명 ID)만 자기 항목 수정**, 그룹당 인원 제한

### 6단계 — 동기화 코드
- "동기화 코드 만들기" → 무작위 코드. 다른 기기에서 입력하면 기록이 합쳐짐.
- 서버에는 코드의 해시만 저장. **마지막 사용 후 30일 지나면 자동 삭제**된다고 화면에 안내.

### 7단계 — 미러전 (나와 닮은 봇과 두기) — 서버 없음
- 코치의 봇 목록에 **"내 성향 봇"** 추가 (저장된 플레이어·종합 분석 결과에서 만들기)
- **실력**: 엔진 깊이 대신 **Maia3를 내 레이팅에 맞춰** 사람이 둘 법한 수 후보를 만들고, 그중 **내 성향(같은 레이팅 대비 두드러진 스타일)** 에 맞는 수를 고른다 → 나처럼 실수도 하는 봇
- **오프닝**: 분석한 내 게임에서 자주 둔 오프닝 수순을 봇이 그대로 따라 둔다 (내 수순이 끝나면 성향대로)
- 확장 가능: 친구 비교 링크·그룹 멤버의 성향 봇과 두기

### 8단계 — 성향 매칭 (지금: 아이디 알려주기 / 나중: 사이트 안 대국 연결) — Supabase
- **목록 등록**: 결과 화면에서 **직접 "매칭 목록에 올리기"를 켠 사람만** 등록, 언제든 내리기 가능 (자동 등록은 추후 검토)
- **본인 확인**: **그 브라우저에서 종합 분석한 아이디만** 올릴 수 있다 (완벽한 확인은 아님 → 신고·삭제 기능과 관리 화면으로 보완)
- **저장**: 사이트(Lichess·Chess.com)·아이디·유형·네 축 백분위·레이팅·주 시간대·갱신 시각. 유형은 종합 분석할 때마다 자동 갱신
- **고를 수 있는 관계**: 나와 가장 비슷한 사람 / 가장 먼(정반대) 사람 / 특정 유형 지정 / 내 약점을 찌르는 상대(내 '이럴 때 조심'과 반대 성향)
- **조건**: 레이팅 범위·같은 사이트·같은 시간대는 **사용자가 선택**, **최근 30일 안에 갱신된 사람만** 항상 적용
- **결과**: 상대 아이디와 유형을 보여주고, 그 사이트 프로필·도전 링크로 연결 (Lichess는 도전 링크 가능)
- **나중에**: 사이트 안에서 성향이 맞는 사람끼리 실시간 대국 연결 (별도 설계)
- 개인정보처리방침에 매칭 목록 항목 추가, 30일 넘게 갱신 없으면 목록에서 자동 제외

### 나중에 (보류)
디스코드 봇, 브라우저 확장 프로그램, 웹 푸시 알림, 국면 공유 캐시. 이메일 리포트는 하지 않음.

## 2단계: 사용자 할 일 (SQL 실행 제외)
1. **Supabase 프로젝트**: 만들어 둠 (2026-10-15) — `stylish-chess`, 서울, 무료, ref `ugxrqdgsqyvqatveqhuu`, URL `https://ugxrqdgsqyvqatveqhuu.supabase.co`. 테이블은 사용자가 SQL로 만든다.
2. **키 전달**
   - Project Settings → API에서 **Project URL**과 **anon(publishable) 키**를 알려 주기. 이 둘은 브라우저에 들어가는 공개용이라 대화에 붙여도 된다.
   - **service_role(secret) 키는 절대 대화에 붙이지 말 것.** GitHub 저장소 → Settings → Secrets and variables → Actions → New repository secret에 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`로 직접 넣기 (오늘의 문제 자동 생성용).
3. **익명 로그인 켜기**: Authentication → Sign In / Providers → **Allow anonymous sign-ins** 켜기 (가입 없이 브라우저마다 고유 ID).
4. **사람 확인(봇 방지)**
   - Cloudflare 대시보드 → Turnstile → 위젯 추가 (도메인 `stylish-chess-engine.pages.dev`) → **사이트 키**와 **비밀 키** 받기
   - Supabase Authentication → Attack Protection → **CAPTCHA 켜기 → Turnstile 선택 → 비밀 키 입력**
   - 사이트 키는 나에게 알려 주기 (공개용)
5. **자동 삭제 기능 켜기**: Database → Extensions → **pg_cron** 켜기 (동기화 코드 30일 삭제용)
6. **Cloudflare Pages 환경 변수** (링크 미리보기가 그룹 정보를 읽을 때): Pages 프로젝트 → Settings → Environment variables → Production에 `SUPABASE_URL`, `SUPABASE_ANON_KEY` 추가
7. **확인**: 개인정보처리방침 변경 문구 검토 (내가 작성), Supabase 무료 등급 유지(Spend cap 켜짐) 확인

## 진행 순서
1단계 → 2단계(사용자 할 일 + 내가 SQL 작성) → 3단계 → 4단계 → 5단계 → 6단계 → 7단계(미러전) → 8단계(성향 매칭).
(7단계는 서버가 필요 없어서 앞당길 수도 있음)
각 단계는 테스트·브라우저 확인 후 main 배포.
